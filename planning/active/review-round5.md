## Findings

- **[severity: bug]** data-raw/host_speeds_calibrate.R:137-149 — group-set matching drops the role check the old key-equality check carried, so a run that gave one role's bucket to another role is now calibrated silently, with each leg's time learned under the other machine's name. This is the round-3 mechanism one axis over: the fix needed to relax identity only for cloud keys (positional `jobN` vs `--cy-workspaces` names), but it relaxed it for every key. The driver assigns `--focal=` lists by position (dispatcher, then workers in `--workers` order, then cyphers; study_area_run.sh:52-54, 413), so an operator who orders the lists differently from the packer's printout (a cloud list before a worker's, the dispatcher's list on a cloud host, two workers' lists swapped) produces a run whose group sets still match the plan's one to one. Reproduced on a copy (scratchpad r5/w1): plan dispatcher{A,B}=m4, job1{C,D}=cloud; run dispatcher{C,D} 100 min, job1{A,B} 125 min. The calibrator exits 0 and prints `| job1 | m4 |` / `| dispatcher | cloud |`, learning m4 0.970 from the cloud host's leg and cloud 1.037 from the dispatcher's; before 40155c90 this run was refused ("the plan gives it ..."). The foreign rule does not catch it (both classes are in the state). Fix: remap keys only within the cloud role — for a plan key matching `^(dispatcher|worker[0-9]+)$` require `run_of[k] == k`; for a plan `jobN` require a run key that does not match that pattern (the driver already forbids `--cy-workspaces` naming those keys, study_area_run.sh:406-408).

- **[severity: fragile]** data-raw/host_speeds_calibrate.R:181-183 and :193 — `--skip=<key>` is now matched against both the run key (`k`) and the plan key (`p$host_key[1]`), and in exactly the case the remap exists for (cloud workspaces out of order) the two namespaces share names with different meanings. Reproduced (r5/w3): plan job1{C}, job2{D}; run job3{C}, job1{D}; `--skip=job1:stall`, meant for the run's job1 (the key every run log and phases row uses), skips both cloud legs (run job1 by `k`, run job3 by plan key job1). It over-skips rather than mis-learns, so the cost is lost evidence plus a history row recording a stall against a host that did not stall. Matching `--skip` keys on the run key only (the table prints run keys in its `host` column, so that is the key the operator reads) removes the ambiguity; the `unknown_skip` check would then validate against `legs$host_key` and `legs$name` only.

- **[severity: fragile]** data-raw/host_speeds_calibrate.R:173-180 with data-raw/study_area_packing.R:168 — when every leg holds a group measured by a class the state lacks, `speeds_calibrate()` stops with the bare "every leg is skipped: nothing to calibrate" before the legs table is printed, so the reason ("groups measured by <alias>, which the state does not hold") and the remedy (name the worker by its log alias) never reach the operator. That is the common case, not an edge: a misnamed or role-key worker's groups spread over every host on the next pack. Simulated with the new rule (r5/conv5.R, 240 groups, 5 hosts, 25 runs): a worker named `m2` whose rows log `Als-Mac`, or named `worker1`, refuses 24 of 25 calibrations and freezes the state (cloud/m4 0.885 throughout), with no reason printed. The accepted tradeoff says "printed with the reason"; here it is not. Print the legs table (or the skip reasons) before calling `speeds_calibrate()`, or catch its all-skipped stop and print them.

## The round-4 fixes, otherwise

- (1) foreign rule. Checked against: role-key legs (a `worker1` leg's own groups log the alias, so its leg is now left out and no longer enters `run_ratio`; consistent); a correctly named worker on its first run (its own groups match `mb == name`, the leg is kept and learned from median; next run it is known); the same worker `--skip`ped on its first run (next run every other leg holding its groups is left out, only its own leg is used, correction 1, it becomes known; converges, r5/conv5.R 0.702); `run_ratio` (left-out legs leave the pool, as skips do); cloud legs (`measured_by` class `cloud` equals the name). Converges to truth with the worker named by its log alias (0.702 at 0.5x, 0.706 at 2x; no worker 0.704), and the round-4 bias (0.63-0.76) is gone. Only defect found is the unprinted reason above. A header-only state file (an empty state) takes the foreign rule with `known = character(0)` while weights and speeds take the equal path; reachable only if a calibration learned nothing, which the seeded state and the required --host-names make unlikely, so not filed.
- (2) group-set matching. SKIPped groups are in `run_wsgs` with `skip=yes`, so they sit in both sets; a host with no groups has rows in neither file, so it drops out of both sides; exact buckets cannot overlap (driver FATAL), and closure buckets give sets that do not match (refused). Defect: the role check above.
- (3) --plan-out needs --host-names: the check runs before any DB work, and the default path (packing machine's alias) can no longer reach a plan. The name is now operator-asserted; nothing the calibrator reads ties it to the machine that ran the leg (the run's own log rows for this run_uid would).
