# Task: Parent attributes on the full network: each segment reads its minimal parent's gradient (#444)

**If we do it:** a habitat rule tuned on the minimal network (`default_minimal`, `cut-min`) applies unchanged on the full network, because each full segment reads the gradient of the minimal segment it was cut from. **If we never do:** knowledge's tuning on minimal segments (`NewGraphEnvironment/knowledge#120`) has no way to deploy on the network link ships, and the transfer cost cannot be measured.

Branch `444-parent-attributes-on-the-full-network` from origin/main `82606e62` (PR #455 merged). Plan approved **parked** on 2026-11-03: this baseline only; the phases run when the resume block in `progress.md` is pasted into a fresh session.

## Context (from plan-mode exploration, 2026-11-03)

knowledge tunes habitat rules on `fresh_default_minimal` (`cut-min`), where no fish record or crossing cuts a stream. link deploys rules on `fresh_default` (`cut-full-top`), whose segments are shorter and read their own gradient. #415's proof showed every full segment lies in one minimal segment (within 1.01 m), so a full segment can read its parent's gradient. The prototype is `data-raw/logs/minimal_breaks_415/parent_<wsg>.csv.gz` (BULK, SETN, MORK, COTR), and knowledge's `knw_parent_join()` already reads that shape (`id_segment, wsg, id_segment_minimal, gradient_minimal, length_minimal, overlap_m, straddle_m`), checking `overlap_m + straddle_m` against the visit's segment length.

Both provincial builds sit in m4's local fwapg (measured 2026-11-03): `fresh_default` (241 groups, link `4dfbfa49`, run `20261103_163715-269b585a`) and `fresh_default_minimal` (241, `193cb8aa`, run `20261102_203300-60ab009d`), both fresh `245c8d8d` (0.52.0), `acc-v5 grad-seg q-fwapg`, `link_dirty` FALSE, one config_hash each, `log.species` identical per group (`{BT,CH,CM,CO,PK,SK,ST}` in BULK on both). `git diff 193cb8aa 4dfbfa49 -- R inst DESCRIPTION data-raw/wsg_run_one.R data-raw/wsg_recompute_one.R`: only `DESCRIPTION`. The same holds from the proof's commit `6bf9ca06` to `193cb8aa`, and BULK has 42,458 full segments in both the proof and `fresh_default`, so the prototype equality check (acceptance 2) is a real test. The `zz415_*` scratch schemas are gone; the check runs against the committed CSVs.

What exploration settled (file refs):
- **Nothing picks a new table up by itself.** Consolidate copies only `consolidate_persist_core` + log specs + `streams_habitat_*` (`data-raw/schema_consolidate.R:237-258`) and leaves others with a NOTE; `host_drop_partials` reads `_HOSTS_PERSIST_CORE` (`study_area_hosts.sh:434`); the verifier and the export name their tables. If `lnk_persist_init()` created `streams_parent`, `test-schema_consolidate.R:375-395` would fail. So the table is created by the builder, post hoc, on the dispatcher where both schemas live. Nothing on the modelling path changes.
- **The pre-run gate's code judgement is inline** in `pretest_record_check()` (`data-raw/pretest.R:597-604`): `pretest_changed_link(repo, a, b, chain)` → `pretest_match(ch, map, chain)` → unmapped refuses, hits other than `none` refuse, `pretest_none_reached()` refuses. These are reusable by sourcing `pretest.R` from a data-raw helper, without editing `pretest.R` (editing it voids every gate record, `PRETEST_RULES`).
- **The grad spec is hardcoded** `gradient=segment` (`R/lnk_vocabulary.R:120-125`); `.lnk_vocabulary_match()` wants one live row per axis *and spec*, so a `grad-parent` row with a different spec is harmless to every config's resolve. `vocabulary.csv` maps to `any` in `pretest_inputs.csv`, so the edit voids the current gate record; the next provincial run needs a new gate anyway (any `R/` modelling change does that).
- **A new `R/` file must match a `pretest_inputs.csv` row** (`test-pretest.R:36`) and, mapped `none`, must not be reached from `wsg_run_one.R` (:44). `lnk_streams_parent()` is called from nowhere on the modelling path.
- Per-group newest closed log row: `DISTINCT ON (watershed_group_code) … ORDER BY watershed_group_code, date_start DESC` with `date_end IS NOT NULL` (`pretest_history_sql`, `study_area_verify.sql`).
- Persist DDL pattern: a `cols_*` named vector + `.lnk_cols_clause(cols, pk)` (`R/lnk_persist_init.R:265`), catalog-first index creation `.lnk_index_create()` (:299).
- data-raw prologue: `LNK_LOAD=loadall` → `pkgload::load_all()`, local fwapg connection, work inside a function (top-level `on.exit` never fires), `getFromNamespace()` for internals (`wsg_recompute_one.R:21-53`). Tests source a data-raw helper into an env with a skip guard (`test-pretest.R:9-18`); DB tests use `skip_if_no_db()` (`setup.R:19`).
- Stale first-party installs on m4: fresh 0.52.0 installed, 0.53.0 released; link's pin is `v0.52.0` and the floor `>= 0.52.0`, and this work calls no fresh function. **Not upgraded**: a pin bump is its own change and voids gate records. link 0.78.1 installed (local) vs 0.78.2: the work runs by `load_all`.

## Decided at the gate (operator, 2026-11-03, parked approval)

1. **Where the code lives:** an exported `lnk_streams_parent()` in `R/lnk_streams_parent.R` (the join, the superset check, the table DDL, the per-group replace inside one transaction) plus a functions-only helper `data-raw/streams_parent.R` (the pair guard, over sourced `pretest.R` functions) and a `data-raw/streams_parent_build.R` driver that judges the pair once and loops groups. The table is created by `lnk_streams_parent()`, never by `lnk_persist_init()` (consolidate test). The new `R/` file maps `none` in `pretest_inputs.csv`.
2. **Columns** (PK `id_segment, watershed_group_code`; index on `watershed_group_code`): `id_segment, watershed_group_code, id_segment_minimal, gradient_minimal, length_minimal, overlap_m, straddle_m` (knowledge's reader needs the last two; they are also the straddle evidence), plus provenance `schema_minimal, run_id_minimal, run_uid_minimal, config_hash_minimal, link_sha_minimal, run_id_full, built_at`. No crossing-based fields, no discharge (issue's fourth box).
3. **Staleness after a re-model:** no modelling-path change (persist, consolidate and `host_drop_partials` all leave `streams_parent` alone, so a re-model leaves its rows behind). `run_id_full` and `run_id_minimal` are stored; the driver's `--verify` names groups whose newest closed `log.run_id` on either side differs from the row's, groups with zero rows, and groups where `overlap_m + straddle_m` is not `streams.length_metre`; RUNBOOK says a `default` or `default_minimal` re-model owes a rebuild of `streams_parent`. (Alternative, not taken: a per-group DELETE of `streams_parent` in `lnk_pipeline_persist`, which touches the modelling path and voids the gate.)
4. **The pair guard** (issue's second box), in the driver: both builds closed, `link_dirty` and `fresh_dirty` FALSE, `fresh_sha` non-NA; one `link_sha`, `fresh_sha`, `config_hash`, `token_acc`, `token_flow`, `token_grad` per schema over every group; the minimal side's `token_cut` is `cut-min` and the full side's a `cut-full-*` token (so a schema paired with itself is refused); `log.species` equal per group; `pretest_fresh_pin()` equal at both shas; `git diff` between the two `link_sha`s over `PRETEST_LINK_PATHS`, chain = union of both configs' `pretest_config_chain()`, through `pretest_match()` + `pretest_none_reached()`: refuse on an unmapped file or a hit other than `none`. `reached` comes from `pretest_reach(asNamespace("link"), pretest_entries(<wsg_run_one.R>, ns))` on the driver's own loaded namespace, never `pretest_reach_repo()` (which re-`load_all`s and stales the driver's bindings); `none` is judged at HEAD, the same limit the gate accepts, stated in the driver header. The gate's `verdict`, `since` range, ancestor test and `PRETEST_RULES` diff do not apply to a pair; no recompute is required (the join reads `streams` only). Raw sha equality not required. The 193cb8aa/4dfbfa49 pair passes: its only changed file is `DESCRIPTION`, mapped `none` (`pretest_inputs.csv:149`), and the fresh pin is `v0.52.0` at both.
5. **`grad-parent` vocabulary row now** (issue's third box): spec `gradient=parent;parent_cut=cut-min`, definition says the full segment reads the gradient of the `cut-min` segment it lies in, through `streams_parent`, and that no link build writes it (knowledge names the "full, parent gradient" setup by it). `introduced` 0.79.0. Test: every shipped config still resolves `grad-seg`; the row is live and matched by no config.
6. **Acceptance 2 is a measured check**, `data-raw/logs/streams_parent_444/prototype_check.R`: the CSV carries ids only (`id_segment, wsg, id_segment_minimal, gradient_minimal, length_minimal, overlap_m, straddle_m`) and the `zz415_*` schemas are gone, so for BULK, SETN, MORK, COTR join the table to the CSV on `id_segment`, which is sound because `.lnk_pipeline_break_reassign_id()` numbers `ORDER BY blue_line_key, downstream_route_measure` (`R/lnk_pipeline_break.R:301-309`): identical cuts give identical ids. Require `id_segment_minimal` equal, `gradient_minimal` within 1e-6, `length_minimal` within 1e-3 m, and the length guards that prove the ids name the same segments: `overlap_m + straddle_m` within 1e-3 m of `fresh_default.streams.length_metre` and `length_minimal` within 1e-3 of `fresh_default_minimal.streams.length_metre` at the matched id (the check `knw_parent_join()` applies; the groups were built on amd64 cloud hosts and arm64 Macs, #361 measured 3.7e-9 m cross-host). Stops on any mismatch; id equality is the result.
7. **Acceptance 1 (knowledge#120's mechanics rerun on `streams_parent`) is knowledge's work**, owed after merge: link ships the table and a one-paragraph note of its shape in the issue (that `wsg` is `watershed_group_code` here, and `length_full` = `overlap_m + straddle_m` is the reader-side guard against a stale table); no CSV exporter.
8. **The province is built in this PR**, on m4's local fwapg, all 241 groups, as the evidence (`data-raw/logs/streams_parent_444/`).
9. Version 0.79.0 (new export, new vocabulary row), bumped as the final commit.
