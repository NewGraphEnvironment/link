## Findings

- **[bug]** `data-raw/study_area_run.sh:664-668` (with `:1741`) — the EXIT trap signals every pid in `WK_PREP_PIDS`, but the array is never cleared after the preps are waited on at line 1741. On every exit after prep (a normal end of run included, hours later) the trap runs `pkill -P <pid>` and `kill <pid>` on pids that were reaped long ago. bash's `kill` builtin passes a raw pid to kill(2), so once macOS's sequential pid counter has wrapped (99999, plausible over a multi-hour run on a machine other sessions share), a reused pid gets SIGTERM, and `pkill -P` also kills all of that process's children: another session's R job, a shell, a `pg_dump`. Fix: `WK_PREP_PIDS=()` right after the wait loop at 1741 (and the trap then only reaches preps still running), or keep only pids that `jobs -p` still lists.

- **[fragile]** `data-raw/study_area_remote.sh:86` / `data-raw/worker_prep.sh:111-120`, enumeration round 3 row 1 — the guard is "any of the variables the leg *exports*", but the mechanism is "anything the leg's R reads from the environment", and a worker's `~/.Renviron` can set variables the leg never exports. Read by the leg's R code and not checked:
  - `LNK_BCFP_MODEL_RUN_ID` (`R/lnk_log.R:1219-1221`): whenever tier 0 answers (the driver exports `LNK_BCFP_MODEL_VERSION`), it is stamped as `bcfp_model_run_id` beside the dispatcher's model version. A stale value there writes another bcfp build's id into every worker row. That is the "another run's provenance" case round 3 set out to close, and verify does not assert this column.
  - `LINK_GIT_DIRTY` / `FRESH_GIT_DIRTY` (`R/lnk_stamp.R:378-383`, env tier first): `check_versions` refuses a wrong `*_GIT_SHA` pin but not a dirty pin. Without a SHA pin, `LINK_GIT_DIRTY=false` makes `link_dirty` FALSE on every worker row. A mid-run uncommitted edit to the clone, which the HEAD-per-group check cannot see (it compares commits), would then pass `study_area_verify.sql`'s `link_dirty` FAIL. `scripts/update_hosts.sh` and `cypher_prep.sh` both write these keys into `~/.Renviron`, so they are present on machines this repo has prepped.
  - `LNK_GUARD_DOWNSTREAM_NOTE` (`data-raw/wsg_run_one.R:107`): turns warn into a recorded override (`status = "override"`, a justification in `log.notes`) that no operator wrote.

  Either add these to the refused set (a separate list, because the test holds `REMOTE_LEG_VARS` equal to the exports), or have the leg export each one empty. An empty export does not help on its own, because R skips an empty `.Renviron` value but applies a non-empty one over the export, so only the prep-side refusal closes it.

- **[security, low]** enumeration round 3 row "names ssh writes into logs" — a worker also names itself. `collect_stamps` writes each host's `lnk_preflight_stamp()` line, whose first field is `.lnk_host()` (`LNK_HOST_ALIAS`, else `Sys.info()["nodename"]`), into `${TS}_stamps.tsv`. Those files are committed (8 tracked under `data-raw/logs/study_area_run/`, host column `m1`, `cypher-job1`, …). `remote_redact_init` collects the target, its host part and `ssh -G`'s HostName, never the worker's alias or nodename. So a worker whose alias differs from its ssh target, or which sets no alias (a macOS nodename such as `<Name>s-Mac-Studio.local`), is named in a committed log while its target is redacted to `<workerN>`. Fix: read the worker's `.lnk_host()` at prep (worker_prep already runs R there) and add it to `WK_REDACT`, or write the worker key into the stamp's host field.

- **[fragile, low]** enumeration round 3 last row — the trap stops worker *preps* before redacting, but a worker *leg* that outlives the driver is not stopped (rightly: it is held). Its ssh keeps the leg log open and writes after the trap's redaction. A killed or FATAL-exiting driver mid-model is the case the redaction exists for (RUNBOOK; `pkill -f study_area_run` does not reach the `ssh` child, whose command line differs). What gets written then is ssh's own end-of-session text, such as `Timeout, server <HostName> not responding.` (the ServerAliveInterval drop) or `Connection to <host> closed by remote host.`, which names the target unredacted in `${TS}_run_<worker>.log`. The row should say legs are not covered, and the remedy printed for a kept worker should include re-running the redaction (as CLAUDE.md already says for the launcher's `run.log`).

## Checked and sound

- `REMOTE_LEG_VARS` and its test: the regex `export [A-Z_]+=` over `remote_leg_cmd`'s output with the stall hook set captures all 12 (PGOPTIONS included). The prep exports none of them (prep is `$WENV bash -s`, no `.remote_cd`), and `check_versions` runs from the clone, as the leg does. So the prep and the leg read the same `.Renviron` (the clone's own, if one existed, would be removed by `git clean -fd`, since `.Renviron` is not in `.gitignore`).
- Redaction lookbehind: dropping `@` from the lookbehind with longest-first order replaces `user@host` whole before its host part. The lookahead still refuses a longer name (`host9.example.x`, `10.0.0.50`). No new over-match found.
- Origin userinfo refusal: `*://*@*` catches `https://u:tok@…`. The driver rewrites the repo's scp-form origin to plain https, so the refusal does not fire on this repo. It would also refuse a credential-free `ssh://git@…` origin, but that fails closed with a clear message.
- bcfp version check: `[[ =~ ^[A-Za-z0-9._+-]+$ ]]` is whole-value (a bracket expression never matches a newline). It runs in `preflight_local` on every spend path, `--preflight-note` does not downgrade it, and it covers the operator's own environment as well as the ledger.
- Live `lnk_persist_init` test: it compares against `information_schema` with base tables only and joins on schema and name. `observations_province` and the other pipeline tables that are not in it live in working schemas, not the persist schema.
- Round 2 enumeration: also checked values not in the table. `VINTAGE_MAX_DAYS` (`case *[!0-9]*`, whole value, `> 0`) and `DISCHARGE` (`fwapg|wet` only) are safe. `WET_LOAD`'s `'` refusal is sufficient inside single quotes.
