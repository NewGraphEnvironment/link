- **[severity: bug]** data-raw/pretest.R:354 (with data-raw/pretest_verdict.R:88-92) — **A gate that modelled nothing clears a run on any installed fresh.** Round 1's fix compares the DESCRIPTION pins at the record's SHA and HEAD, but the pin is a proxy: what runs is the installed fresh. When every change since the last run maps to `none` or `unexercised`, the verdict writes `fresh_sha = NA`, and `pretest_record_check()` then skips the fresh comparison entirely (`if (!is.na(rec$fresh_sha) && ...)`). Probed: a no-model pass record with `fresh_sha = NA` returns `ok = TRUE` for `fresh_sha = "deadbeef_any_installed_fresh"`. The verdict's comment says "the driver's own pre-flight still checks the tree and fresh", but `preflight_local()` only checks that fresh's SHA resolves and is clean, never which fresh it is; nothing on the dispatcher compares the installed fresh with the DESCRIPTION pin (installed here: `RemoteRef v0.44.0`, but nothing asserts it). So a fresh installed from a branch or a newer tag, with the pin unchanged, reaches a dispatcher-only or worker run with no gate. Cyphers install from the pin, so host parity would catch it only when cyphers are in the run. RUNBOOK §8d's "its fresh SHA is the installed one" is false for this record. Fix: have the no-model path record the installed fresh (`link:::.lnk_pkg_git_state("fresh")$sha`, the value `preflight_local()` passes as `--fresh-sha`) so the existing comparison runs, or refuse a record whose `fresh_sha` is NA.

- **[severity: fragile]** data-raw/pretest.R:367-375 (and pretest_pick.R) — **The `none` classification of link files is checked only by test-pretest.R, which neither the gate nor the driver runs.** The record check clears every post-gate change to a `none` file. If a commit adds a call from a reached file to a `none` file (for example, the pipeline starts calling `lnk_rollup_wsg()`), that commit voids the record and a new gate passes on it. A later edit to `lnk_rollup_wsg.R` is then read as off-path, and the record clears the run without a gate. Or the record check could treat a `none` file as moved when it is reached at HEAD.

- **[severity: fragile]** data-raw/pretest.R:288-296 — **History is not filtered by config.** `pretest_history_sql()` reads every group's newest finished build in the schema, whatever its `config_name`. - **[severity: fragile]** data-raw/pretest_run.sh:77-78,110,115,223 — **A relative `--out=` names two directories.** The pick and the verdict run under `cd "$REPO_ROOT"`, while `mkdir`, `range.txt`, `picks.tsv`, `exits.tsv` and the group logs use `$OUT` as given, relative to the caller's directory.
