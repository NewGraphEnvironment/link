## Findings

- **[fragile]** `data-raw/recompute_audit.R:68-71, 78, 94-95` — the dispatcher arm still compares across two clocks when a group is on the dispatcher **and** a remote host (closure-mode overlap, `run_wsgs.tsv` lists it under both). Consolidate copies the remote host's `log` rows into the dispatcher's `log` (#354; `fresh_default.log` holds `host` = `cypher-job1..3` rows beside `m1`), and the `model` query takes the newest closed row for the run by `date_start` with no filter on who wrote it. When the cypher's copy is the newest, `land_disp[d]` is the **cypher database's** `now()`, compared against `log_recompute.date_start` on the dispatcher's VM clock: exactly the cross-clock comparison fix 1 removed, one axis over. A miss is harmless here (the remote arm, on the driver clock, is binding because an overlapped host is consolidated after the dispatcher leg ends), but a VM clock behind the cloud host's by more than that consolidate gap reports a false `EARLY`, fails the run and prints the "RE-MODEL each of them" remedy. Fix: in the dispatcher arm read only the dispatcher's own rows (filter `log.host`, or exclude the `run_id`s a consolidate copied), or skip the dispatcher arm for a dependency that also has a remote host in the run.

- **[fragile]** `data-raw/study_area_finish.sh:701` with `data-raw/recompute_audit.R:57-58, 97-100` — the audit's only record of launch times is the copy made by `cp "$RC_DIR/launched.tsv" … 2>/dev/null || true`, and `RC_DIR` (the original) is deleted on success at line 653, before the audit runs. If that copy fails, the audit reads "no launched file" as "the scheduler started nothing": every remote-dependency pair becomes `start_unrecorded`, which never fails, and the run prints "✓ recompute audit: no group started before a group it reads had landed" having checked none of them. That is the guard failing toward pass on the one check the run relies on for early starts. Fix: when `$RC_DIR/launched.tsv` exists, make a failed copy set `RC_AUDIT=unread` / `RECOMPUTE_FAIL=1` (or pass the original and delete `RC_DIR` after the audit).

- **[fragile]** `data-raw/logs/recompute_early_374/ab_compare.R:17, 48` — passes vacuously, the defect round 1 fixed in `digest_test.R`. A wrong or absent schema `a` gives `tabs` = 0 rows, `res` = `NULL`, `all(logical(0))` = `TRUE`, and the script prints "identical" and exits 0; a group list that matches no rows gives `n_a == n_b == 0` everywhere, also "identical". The committed `ab_compare_a2.tsv` / `ab_compare.tsv` carry non-zero counts, so the recorded evidence stands; a re-run with a typo would not. Fix: stop when `tabs` is empty or `streams_access`'s `n_a` is 0.

No bug or security finding in the scheduler, the readiness functions, the fallback pool, the dependency map or the view key.
