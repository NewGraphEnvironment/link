The build refuses on any modified tracked file (`git status --porcelain --untracked-files=no`, line 77), but every invocation rewrites those tracked files: `--verify` rewrites `verify.tsv` (and returns before the clean check), and a build writes `pair.tsv` before building and `build.tsv` (with per-group minutes, so never byte-identical) after. So the workflow the RUNBOOK prescribes — run `--verify`, and if it names a group rebuild with "the same command without `--verify`" — refuses with "the checkout has uncommitted changes" exactly when it matters: a stale group means the newest run_ids differ from the committed `verify.tsv`, so the file is modified. Likewise any second build attempt (after a refused pair, which still writes `pair.tsv`, or after a failed group) refuses until someone commits or discards the evidence. The clean-tree check is meant to guard the `load_all`ed code, not the driver's own logs. Fix: exclude the out dir from the dirty check (e.g. `-- . ':(exclude)data-raw/logs/'`), or default `--out` outside the tracked tree, and correct the RUNBOOK command.
