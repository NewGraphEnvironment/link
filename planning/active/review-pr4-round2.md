## Findings

- **[severity: fragile]** data-raw/logs/hosts_ready_439/README.md:14-18 — Round 1's finding 3 has been fixed one axis over. The README still names the `log.json` comparison as the check before launch, and `log.json` is not the identity of what the cloud hosts load. Prep runs `bash snapshot_bcfp.sh` (`cypher_prep.sh:259`). That script loads PSCIS and CABD from live APIs, and `observations.parquet` and `modelled_stream_crossings.gpkg.zip` from the bchamp object store (`nrs.objectstore.gov.bc.ca/bchamp`, not `s3://fresh-bc`). `log.json` is the label of the ng-prod bcfishpass build. `observations.parquet` is bcfishobs's own publish: its Last-Modified is 2026-09-22, five weeks before `log.json`'s 2026-10-28. It can be republished with no change to `log.json`, and the script says as much at line 124 ("useful when upstream parquet drift differs from bcfp git SHA"). So a `log.json` comparison passes when either object has a new version, and it cannot see PSCIS or CABD at all. The comparison that tests the property is a HEAD of the two bchamp URLs, comparing `x-amz-version-id` with `load_stamps.csv`. Today they still match: 1790057230537 / 1793134826715. PSCIS and CABD cannot be pinned before launch, and the README should say that. The example "a new build that changed only the views would pass" names a case with no cross-host effect: cyphers load no views (no `--with-bcfp-views` at prep) and workers do not snapshot. Meanwhile the real case that nothing guards before the writes (a republished observations object, or PSCIS updated between the 09:42 loads and cloud prep) is not named.
  - **Rule:** code-check.md "A proxy is not the property"
