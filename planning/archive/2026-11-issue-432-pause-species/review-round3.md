## Findings

- **[severity: fragile]** data-raw/habitat_validate.R:83-90 — the refusal keys on the bundle's current `species_paused`, not on what the scored schema holds. Its comment ("A species a bundle pauses has no habitat to score in a build of it") is true only of builds made at this version. `fresh_default` (every group built 2026-10-23 at 0.68.0, until the next provincial run) and every existing `score*` schema hold KO and RB habitat built while they were modelled, and `lnk_habitat_validate()` itself never reads `cfg$species` (its predicates come from the bundle's rules, which still carry KO and RB), so `habitat_validate.R --bundles=default:fresh_default --species=RB` ran before this branch and is now refused. There is no escape: another config is refused because `<schema>.log` records the groups under `default`. The precise scope is the schema's own record of what was classified: `log.species` of each scored group's newest build (as the verifier's new assertion reads it), refusing only where no scored group's build classified the species. Same mechanism as round 2's finding, pointed at what is read rather than what is built.
