1. **fragile** `tests/testthat/test-driver_config.R` (`run_sh_driver`, and its use for `recompute_parity.sh` / `recompute_sweep.sh` with `c("LKEL","default")`): `system2(env = )` adds to the inherited environment, and `run_sh_driver` sets no `LNK_SCHEMA=` (unlike `run_r_driver`, which sets `LNK_SCHEMA=`). If the developer's shell or Renviron exports `LNK_SCHEMA`, the "LNK_SCHEMA is required" refusal does not fire and `recompute_parity.sh` goes on to run for real: psql against localhost, `DROP SCHEMA zz_lnk_parity_bak`, backups of the schema, real recomputes under `default`. A test meant to prove a refusal then writes the database. Fix: pass `env = c("LNK_SCHEMA=", env)` in `run_sh_driver` (and `LNK_RUN_LABEL=`). **Rule:** code-check.md, "A fixture that cannot reach the failure mode" / "Restore the bug and prove the guard fires" (the guard's test depends on ambient state).

The header comment at line ~30 still says LNK_CONFIG defaults to `bcfishpass`, which is now false. **Rule:** none (ordering of a guard after its expensive side effect).
