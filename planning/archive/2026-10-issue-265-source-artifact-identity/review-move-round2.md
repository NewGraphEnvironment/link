## Findings

- **[severity: fragile]** R/lnk_artifact.R:411-441 — `lnk_artifact_read()` decides `status` from the record alone. It never checks that the recorded table still exists. Before the move that made no difference after a `state_clean.sh` full wipe, because `DROP SCHEMA fresh CASCADE` removed the artifact table along with `fresh.modelled_stream_crossings`. Now the `loader` row survives the drop.
  - **How the state is reached:** `state_clean.sh` step 5's snapshot dies before `artifact_record.R --clear` runs, for example on the prereq check for `bcdata`/`ogr2ogr`/Parquet. state_clean never checks the backgrounded snapshot's status (`wait` with no PID, line 187), so the wipe still reports complete.
  - **What it shows:** `lnk_artifact_read()` then reports `fresh.modelled_stream_crossings` as `recorded`, with version `1791321558612` and `n_rows` 524,578, for a table that does not exist. `.lnk_log_inputs()` would copy that identity into `log_input.artifact_*` beside `row_count` NULL for any run opened in that state.
  - **What stops it:** the gate. `lnk_preflight_vintage()` classes the table `absent` before it reads stamps, and the pipeline cannot read crossings without the table, so no run can complete in this state. The harm is limited to the exported reader and the log row giving a confident answer about a load that is gone.
  - This is reporting, not gating. The only path that recreates the table is `snapshot_bcfp.sh`, which `--clear`s first, so consistency is restored on reload. Verified: `grep` finds no other writer of `fresh.modelled_stream_crossings` in R/ or data-raw/.

Everything else checked holds:

- **Outliving a dropped `fresh`, gate side:** in `lnk_preflight_vintage()` an absent table goes into `absent` before stamps are consulted, and stamps are applied only to `present` (`R/lnk_preflight_vintage.R:120-145`). A stale loader row cannot pass a dropped table.
- **Reload restores consistency:** `snapshot_bcfp.sh:180` runs `artifact_record.R --clear` (delete this host's loader rows for the four vintage primitives) before any load. A load that dies part way leaves them `unstamped`, which fails. `--clear` itself creates `provenance`, so it no longer depends on `fresh` existing. The script still creates `fresh` at line 185, before step 3 writes into it. `wsgs_run_pipeline.sh --reset-schema --schema=fresh` runs the snapshot right after its scoped drop (lines 223-233).
- **Probe rows now persist across a wipe.** This is intended: keep-earliest-probe, and RUNBOOK says plainly that a reload keeping the row count is invisible to it. The removed RUNBOOK line ("probe rows come back on the next snapshot") was the one that became false, and it is gone.
- **Schema creation and permissions:** `.lnk_artifact_create()` runs `CREATE SCHEMA IF NOT EXISTS provenance`. PG checks the database CREATE privilege before the IF NOT EXISTS short-circuit, exactly as it did for `fresh`, so behaviour is unchanged. Every writer and reader runs as `postgres`: cypher_prep.sh:241, state_clean.sh, host_vintage.R, the test `skip_if_no_db()`. The existence probes (`information_schema.tables`, `to_regclass`) need no search_path.
- **Tests in a DB without `provenance`:** each DB test calls `lnk_artifact_record()`, which calls `.lnk_artifact_create()` before its first write, so the `withr::defer` DELETEs find the table.
- **Nothing enumerates schemas or `log_%` tables in a way the move changes:**
  - `schema_consolidate.R` copies only persist-schema tables carrying `watershed_group_code`, and its backup is `pg_dump --schema=<persist>`.
  - `state_clean.sh`'s pattern does not match `provenance`.
  - No code looks for `log_%` in `fresh`.
- **Mixed-version hosts:** on cyphers, `artifact_record.R` (pkgload, source tree) and `host_vintage.R` (pak-installed) both come from the same checkout, installed by cypher_prep. On the dispatcher both run from the source tree. On local fwapg the old `fresh.log_source_artifact` is gone (`to_regclass` NULL). `provenance.source_artifact` holds m1's 4 loader and 253 probe rows, and the four loader rows match the archive README's Measurement figures.
- **Docs:** CLAUDE.md, the RUNBOOK (§6b and §8d), `research/upstream_input_provenance.md`, the archive README and the state_clean.sh header contain no statement made false by the move. 252 HEADed artifacts plus the one `derived` row account for the 253 probe rows.
