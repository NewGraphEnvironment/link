## Findings

- **[severity: bug]** `data-raw/study_area_packing.R:186-187` (`speeds_calibrate`). The round-1 fix (#2, damp toward the stored factor) left the correction measured against the **packed** speed: `projected` is weight / packed, and then `observed <- packed / correction`. So `observed = truth × Σ(W/truth) / Σ(W/packed)`, and the scale it carries depends on the speed the run was packed at. When packed ≠ old (a `--host-speeds` run, or a plan packed from an older state), that scale moves every learned name **in** the run and leaves every name **not** in it (skipped, or absent) where it was. That breaks ratios, which the accepted-tradeoff note does not cover. In the one-name case it simply writes in 30 % of the CLI value. Both shown in a copy (`probe_cal.R` in the scratchpad):
  - Truth all equal, state `m1 = m4 = cloud = 1`, a run packed with `--host-speeds=1,0.45,0.45,0.45` (m4, cloud) and balanced loads. The calibrator observes 0.5875 for both, and m4 and cloud go to 0.876 while m1 stays at 1. With no evidence about m1, the state now has m1 1.14× faster than m4. A later run with m1 as a worker packs on that.
  - One usable name (cloud left out by `--skip=cloud:stall`, or by its `account` failing), packed with `--host-speeds` m4 = 1.5, truth equal. The correction is identically 1, so `observed = packed = 1.5`, and m4 goes 1 → 1.15 against cloud's unchanged 1. That is the round-1 defect: the CLI speed leaks into the state.

  The new test "an update is damped toward the stored factor…" cannot reach this. It has only two names, both in the run, both unskipped, so the common scale cancels in their ratio and nothing is left out to compare against. The claim in CLAUDE.md, RUNBOOK §8d ("so the observation does not depend on the state … informs the learned factor without replacing it") and the function header is therefore still false in these cases.

  Fix, tried in a copy: project each leg at the stored speed before the ratios, `projected_old = projected × packed / old`, then `observed = old / correction`. The probe then gives no change in both cases. The whole of `test-study_area_packing.R`, including the 20-run convergence simulation and the damping test, still passes against the mutant (`LNK_TEST_PACKING_LIB`), because `projected_old == projected` whenever a run is packed at the state.

- **[severity: fragile]** CLAUDE.md:19 and `data-raw/study_area_buckets.R:298`, "Every leg ran 11 to 17 % over the minutes estimate". This is the round-1 fix #4 one axis over. 11 to 17 % is the estimate's shortfall, `pred/meas − 1` = −11.4, −16.5, −14.8, −11.1 % (fit.md's `minutes | equal` row, KTSU and OKAN left out). The two restatements are inverted, and round 1's "11 to 20" was nearer for "ran over".

- **[severity: fragile]** `data-raw/study_area_buckets.R:163-168` against `study_area_packing.R:149-153`. The packer accepts `--host-speeds` that give cloud hosts different speeds (e.g. `1,0.45,0.5,0.45`) and writes a plan with them. `speeds_calibrate` then refuses that plan ("one name packed at two speeds"), so a paid run packed that way cannot be calibrated, and nothing says so until after the run. The rule "every cloud host is one class" is enforced on names in the packer but on speeds only in the calibrator. The packer should refuse unequal speeds within the cloud class, as it already refuses a cloud host not named `cloud`.

- **[severity: fragile]** `data-raw/host_speeds_calibrate.R:154,160-163`. `--skip` matches the leg's **name** only, and `--skip=job2:…` stops with "names no host in the plan". A stall on one cloud host (EUCH's 21.9 min on a host, CLAUDE.md #369) therefore cannot be left out alone. The operator either drops all three cloud legs, which leaves the dispatcher as the only name, its correction ≡ 1, and puts it in the single-name case of finding 1, or books the stall into `cloud` and `run_ratio`. The per-leg skip path already exists for `account` and "no model row" (keyed by `host_key`). Accepting a role key in `--skip` for the operator's case would close this. RUNBOOK §8d says "a host named by `--skip`", which reads as if one host could be named.
