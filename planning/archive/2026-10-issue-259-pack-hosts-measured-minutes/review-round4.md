## Findings

- **[severity: bug]** data-raw/host_speeds_calibrate.R:150 with data-raw/study_area_packing.R:125-129 and data-raw/study_area_buckets.R:148-150 - on the DEFAULT `--host-names` path, any persistent worker biases the learned dispatcher/cloud ratio, persistently, even when its own leg is `--skip`ped. The default names a worker `worker1` (a role key, never learned), and its log rows carry its own alias or node name, which the state never holds, so every group the worker measured is normalized at the state's median forever. When those groups move to the dispatcher or a cloud host in a later run, their projected weight is `minutes x median` instead of `minutes x worker truth`, and that error is booked into the dispatcher's or cloud's correction. Simulated (scratchpad r4/conv.R: m4 truth 1, cloud 0.7, one worker, 240 groups, 25 runs, the shipped helpers incl. plan_weights_at): cloud/m4 converges to 0.704 with no worker and to 0.702 with a worker named under its log alias, but to 0.63-0.66 with a default-named worker at 0.5x (0.64 when its leg is skipped) and 0.70-0.76 with one at 2x. RUNBOOK "Role keys are never learned" implies an unnamed worker only goes unlearned; it also mis-teaches the hosts that are learned. The accepted tradeoff ("a worker whose alias differs gets the median for normalization") covers the worker's own packing, not this propagation. The plan already carries `measured_by`, so the calibrator can see it: leave out of the leg (or refuse, or at least print) groups whose `measured_by` class the calibrating state does not hold and that ran on another name - the "moved from a median-normalized class" population.

- **[severity: fragile]** data-raw/study_area_buckets.R:134-138 vs data-raw/study_area_run.sh:375,413 and data-raw/host_speeds_calibrate.R:134-143 - the plan's `host_key` for a cloud host is synthesized positionally (`job1..N` after the workers), while the driver keys cloud legs by the operator's `--cy-workspaces=` names, in that order. They agree only when the run uses exactly `job1,job2,...` in order. A run on `--cy-workspaces=job1,job3` (job2 held as a kept host, the case #347/#369 produce) has run_wsgs/phases keys `job1, job3` against the plan's `job1, job2`, so the calibrator stops with "the plan gives it N groups and the run 0 ... calibrate against the plan the run used" - a correct run refused, with a remedy that is wrong (the operator did use that plan). Fails loud, not silent; but it is the round-3 mechanism (one identity, two sources, agree on the default path only), and nothing in the plan lets the calibrator map positions to the driver's keys. Either match each plan host to the run host holding the same group set (the per-host groups check already computes both sides), or have the packer take the cloud keys.

- **[severity: fragile]** data-raw/study_area_buckets.R:142-150 - the dispatcher's default name is the PACKING machine's alias (LNK_HOST_ALIAS or node name), and the calibrator learns whatever name the plan carries for the `dispatcher` leg. If the packer is run anywhere but the dispatcher (the dispatcher moved m1 -> m4 this month), the dispatcher leg's speed is learned under the wrong machine's name, silently, and the dispatcher's own groups (log class m4) are then "movers" against name m1. Nothing ties the plan's dispatcher name to the machine that ran the leg; the calibrator could compare it with the `measured_by` class of the dispatcher's own previously-logged groups, or the packer could refuse a defaulted name when it is not the dispatcher (it cannot know) - so at minimum require `--host-names` when `--plan-out` is given.

## Round-3 fix verified

Re-ran the pack-on-older-state check (scratchpad r4/sim.R) through plan_weights_at with raw minutes, same assignment and actuals, varying only the pack-time state / --host-speeds: learned factors identical to 7 digits for S1/S1, S0/S1, NULL/S1, --host-speeds/S1 (cloud 0.8835, m1 1.0549), and S0/S7 = S7/S7 = truth (0.7, 1). Calibrating with no state: identical whatever the pack state. With 20 of 240 groups unmeasured (median weight kept), the pack state moves the result by at most 0.003 (the accepted residual). End to end through the real script (r4/run, plans written with buckets' write.table args, `na = ""`): two plans packed at different states give identical history rows apart from the `packed` column. The round trip `""` -> NA for minutes and measured_by works; host_class() is idempotent on stored classes. No new defect found inside the fix.
