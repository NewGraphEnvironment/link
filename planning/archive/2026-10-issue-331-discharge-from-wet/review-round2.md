# Code-check round 2 — branch 331-phase5 (HEAD 9645d736)

## Findings

- **[severity: fragile]** data-raw/discharge_wet_load.R:70-74 — the remedy in the new FAIL message is wrong for the dispatcher this repo actually runs on. It tells the operator to run `data-raw/discharge_wet_load.R --force` on the dispatcher. `--force` calls `wet_db_load(months = 0, pick_only = TRUE)`, which replaces the whole `historical` scenario. On a dispatcher holding every month and source (the local fwapg holds the 103 M-row full load; its comment has no `; subset` suffix), following the message deletes about 98 M monthly rows to leave only the pick. The script's own header (lines 17-18) states that consequence, but the message the operator acts on does not. It is also the only route this script offers, because without `--force` the dispatcher (which gets no `--expect-load`) always takes the "already loaded" branch. A remedy is code the caller will run. The message should name a reload that keeps the dispatcher's shape, for example `wet::wet_db_load(conn, wet::wet_catalog())` for a full load, or warn about what `--force` drops.

- **[severity: fragile]** data-raw/study_area_run.sh:281-293 with data-raw/cypher_prep.sh:280 — the consistency guard fails toward pass. `WET_LOAD` is computed with `2>/dev/null || true`. If that Rscript errors, or `res$ok` is FALSE at that moment, `WET_LOAD` is empty. cypher_prep then passes `--expect-load=`, which `discharge_wet_load.R` turns into `NA`, so it does no check. Each cypher then loads whatever is published, with nothing comparing it to the dispatcher's load. The dispatcher gate at line 657 runs separately and can pass on a later, successful call (a transient connection error, for example). The check is then off without a word. With `DISCHARGE=wet`, an empty `WET_LOAD` should be fatal: after the gate passes, or in cypher_prep when `CYPHER_PREP_DISCHARGE=wet` and `CYPHER_PREP_WET_LOAD` is empty. Lower likelihood than the first finding, but it is the exact failure fix 2 was written to close.

- **[severity: fragile]** data-raw/wsgs_run_pipeline.sh:270 — a second caller of `cypher_prep.sh` was not updated. The older multi-host orchestrator takes `--config=<name>` (line 70) and still runs `CYPHER_PREP_BRANCH='$PREP_BRANCH' bash /tmp/cypher_prep.sh` without `CYPHER_PREP_DISCHARGE` or `CYPHER_PREP_WET_LOAD`. Run with a wet config (`default_tuned` after this branch's next phase), no cypher loads wet. Every cypher WSG then stops at prepare (`.lnk_discharge_join`'s preflight). wsgs_run_host.R records those as per-WSG errors and the run goes on (its smoke step does not cover the cyphers). That script also has no dispatcher discharge gate. It is the fix-lands-in-one-of-two-callers shape. Either thread the source and load id through it, or have it refuse a config whose `discharge_source` is not `fwapg`.
