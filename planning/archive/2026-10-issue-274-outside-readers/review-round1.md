## Findings

- **[severity: fragile]** data-raw/recompute_readers_check.R:157-162. When readers exist but none of them has a `log` row, `last` has 0 rows. `data.frame(wsg = last$wsg, has_log = TRUE, …, downstream = "pass")` then raises "arguments imply differing number of rows: 0, 1". I reproduced this in R with the same constructor. The case is real: a schema whose readers all predate the log tables. In `fresh`, 30 of the field scope's 35 held readers have no log row, so a smaller partial run into `fresh` can reach it. The script exits 1 and `recompute_readers` falls back to naming every map candidate as `unchecked` / `check_failed`, when each one should be `refused` / `no_log`. Nothing is recomputed wrongly. But the report says "NOT checked" for a check that could have answered, and it names candidates the schema does not hold. To fix it, build `facts` with `has_log = rep(TRUE, nrow(last))` and `downstream = rep("pass", nrow(last))`, or return a typed 0-row frame when `nrow(last) == 0`.
  - **Rule:** code-check-r.md "`data.frame()` recycles a scalar against a zero-length column" ; code-check.md "Zero-length, empty, and unset are three different things"

- **[severity: fragile]** data-raw/recompute_readers_check.R:111-116 and 119-124 (and `readers_classify`'s `expect`). The compatibility test requires the reader's build to have `fresh_dirty` FALSE. It never tests the fresh the recompute will run now. `expect` carries only `fresh_sha`, and `refuse_all` checks the link tree on READERS_PATHS and the run's config hash, but not `st$software$fresh$dirty`. Tier 3 of `.lnk_pkg_git_state()` (a fresh found through its `.git`) can report the same sha with `dirty = TRUE`, or NA. Either way the reader is classified `recompute`, and the irreversible gate runs under an engine that is not the one its build used. The run's own rows would carry `fresh_dirty` TRUE and fail `study_area_verify.sql`, but that check comes after the readers were rewritten. This contradicts the stated rule that "anything unknown refuses". To fix it, add a `refuse_all` reason (e.g. `dispatcher_fresh_dirty`) when `!identical(st$software$fresh$dirty, FALSE)`.
  - **Rule:** code-check.md "A guard that fails toward pass"
