## Findings

- **[severity: bug]** data-raw/study_area_run.sh:401-403 — the new refusal `[ "$STALL_AFTER_MIN" -lt "$STATEMENT_TIMEOUT_MIN" ]` runs whether or not `--stall-sample-after` was given, against its default of 10. So `--statement-timeout=N` for any N from 1 to 10, passed alone, is now refused, with a message naming a flag the operator never passed. `--statement-timeout=1` can never run at all, because the smallest `--stall-sample-after` is 1 and it must be below the bound. That breaks what the driver's own header (line 134, "default 30, 1..1440") and RUNBOOK §8d's #371 section still promise: "`--statement-timeout=<minutes>`, default 30, 1 to 1440" (RUNBOOK.md:2490) and "With `--statement-timeout=1` the group fails after a minute, and the run carries on" (RUNBOOK.md:2533, the documented way to exercise the bound with `LNK_TEST_STALL_WSG`, kept beside this branch's edit to that paragraph). The refusal is meant to catch a threshold the operator chose that can never fire, so refuse only when `STALL_AFTER_SET=1`. When the default is at or above the bound, the default should give way instead (lower it, or turn the sampler off for the run and say so in the banner), not refuse a run that was valid before this change. The new test asserts only the explicit pair `--statement-timeout=5 --stall-sample-after=5`, so it cannot see this.
  - **Rule:** code-check.md "A guard's scope, escape hatches, and remedies" ; code-check.md "A guard that fails toward pass" ; code-check.md "Documentation Staleness"
