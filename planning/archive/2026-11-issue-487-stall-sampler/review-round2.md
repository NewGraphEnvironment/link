## Findings

- **[severity: fragile]** data-raw/wsg_run_one.R:148, with data-raw/study_area_run.sh:413 and R/lnk_stall.R:151. The `[wsg_run_one] <WSG> stall samples: <file>` line after a TIMEOUT is gated on `bound_ms > stall_after_min * 60000`. That condition stands in for "samples were written", and the round-1 default makes it fail. A row is written only when a check lands in (statement start + after, statement start + bound]. Checks run every `every_s` (60 s), and the first runs `every_s` after the watch starts, which is after the sampler's own `load_all()` and connect. Under `--statement-timeout=1` the default threshold is now 0.5 min, so that window is 30 s against 60 s check spacing: at best about one chance in two of any row. In the exercise RUNBOOK §8d names for a 1-minute bound (`LNK_TEST_STALL_WSG`), `pg_sleep` starts as soon as the guard returns, while the sampler's first check comes about 60 s plus its `load_all()` after launch. So the statement is usually cancelled before any check, and run_stalls writes no file. The TIMEOUT path still prints `stall samples: <ts>_stall_<WSG>.tsv`, naming a file that does not exist. The comment above it ("Samples exist only when the bound outlasted the sampler's threshold") states the same proxy as fact. The driver's INCOMPLETE block guards with `-f`, so only the host-log line misleads; the fractional value itself breaks nothing downstream. I checked the banner, the `'0.5'` remote export, `wsg_run_one.R`'s validation (`> 0`, fractional allowed), `stall_after_min * 60` passed as "30" to the sampler, and the bash `-ge` test, which runs before 0.5 is assigned. Possible fixes: gate the line on `bound_ms > (stall_after_min * 60 + stall_every_s) * 1000`; or, for a short bound, start the first check at `min(every_s, after_s)` rather than `every_s`; or leave the line out when samples cannot be guaranteed.

- **[severity: fragile]** data-raw/study_area_finish.sh:466. In `for w in $(cut -f1 "$tmp" 2>/dev/null | LC_ALL=C sort -u)`, `cut` runs in the operator's locale. The awk before it and the `sort` after it both run under `LC_ALL=C`. macOS `/usr/bin/cut` in a UTF-8 locale stops at the first line holding an invalid byte, and every later line is lost. I measured this here: `printf 'AAAA\tok\nBBBB\tbad \xe2\x9c\nCCCC\tok\n'` under `/usr/bin/cut -f1` prints only `AAAA`, then `cut: … Illegal byte sequence`, with exit 0. GNU cut, first on this shell's PATH, prints all three, so the failure shows only on a host where `cut` is the system one. `$tmp` keeps any tagged line whatever follows the tab. A blocker's or leader's query with a non-ASCII character in a comment, cut mid-glyph by a dropped ssh session or a killed writer (the case `run_timeouts`' comment already names), drops every group whose first stall row comes after that line. Those groups get no `_stall_` file and no summary line, and nothing reports the loss, because the stderr is discarded and the `for` list hides it. Fix: `LC_ALL=C cut -f1`, or take the group codes in the `LC_ALL=C awk` that writes `$tmp`.
  - **Rule:** code-check-shell.md "macOS `sed` dies on an invalid byte, and GNU sed misparses it"
